# MagicMD v0.7.2

v0.7.2 重点解决采集内容进入业务系统后的两个问题：Markdown 是否能稳定渲染，以及媒体资产是否能由调用方明确控制。

这一版系统化加固了 Markdown 清理和质量扫描，覆盖加粗边界、游离强调符号、空图片、图片外层强调、转义加粗、裸链接、仅地址代码块、引用式链接和嵌套容器等常见采集缺陷。同时，SDK 新增结构化视频资产返回，让 HaoGit 等调用方可以读取视频元数据，并根据自己的存储策略选择归档视频或只保留原文入口。

## Markdown 格式修复

- 修复 `**重点**正文`、多余 `****`、孤立 `**` 和不平衡强调符号等容易导致加粗渲染失败的问题。
- 清理空图片、图片外层错误强调和被拆散的链接图片结构。
- 修复正文中的成对转义加粗、裸链接边界和只包含项目地址的错误代码块。
- 保留行内代码、围栏代码块、嵌套列表与引用、带括号的图片 URL 和标题，以及引用式链接定义，避免清理过程改变原文语义。
- `repair_markdown_quality()` 保持幂等，同一内容重复修复不会持续产生变化。

## 质量扫描

- 扩展 `scan_markdown_quality()`，识别游离或冗余强调符号、空图片目标、相对本地视频、异常标题层级、可疑代码语言、代码中的不换行空格和未重写的微信媒体地址。
- 支持普通链接、图片、嵌套 Markdown 节点和引用式链接，质量检查不会把链接目标中的特殊字符误判为正文格式错误。
- 批量转换报告可以把这些质量信号交给下游审核流程，区分可自动修复的问题与需要人工确认的问题。

## 视频 SDK

- 新增公开类型 `ConvertedVideo`。
- `ArticleConversionResult.videos` 返回视频来源地址、Markdown 路径、本地文件路径和扩展名。
- 重试转换会复用已经下载的视频，并为新视频分配后续路径，不覆盖已有文件。
- 固定文件名或 Markdown 路径模板发生重复冲突时会安全停止该视频下载，并写入 warning，避免无限分配或静默覆盖。
- 本地媒体路径只会解析到生成内容包内部的真实文件。

如果业务系统不希望保存视频，可以在 MagicMD 配置中关闭下载：

```toml
[videos]
download = false
```

调用方仍然可以根据文章中的视频标记提示用户前往原文观看。

## 浏览器兼容性

- 发布依赖继续约束 `playwright>=1.60,<1.61`，与当前稳定版 Camoufox 0.4.11 的浏览器协议保持兼容。
- npm wrapper 固定调用同版本 Python 包；Windows 使用 `uvx.exe`，macOS 和 Linux 使用 `uvx`。

# MagicMD v0.7.2

v0.7.2 focuses on two requirements for production ingestion: Markdown that renders reliably and media assets that remain under the caller's explicit control.

This release systematically hardens Markdown cleanup and quality scanning across strong boundaries, orphan emphasis markers, empty images, emphasized images, escaped strong markers, bare URLs, address-only code fences, reference-style links, and nested containers. The SDK also adds structured video results so consumers such as HaoGit can inspect video metadata and choose whether to archive the files or keep only an original-article entry point.

## Markdown Repair

- Fixed strong text followed directly by prose, redundant `****`, orphan `**`, and unbalanced emphasis markers.
- Removed empty images, invalid emphasis around images, and fragmented linked-image structures.
- Repaired paired escaped strong markers, bare URL boundaries, and code fences that only contain a project address.
- Preserved inline code, fenced code blocks, nested lists and blockquotes, parenthesized image destinations and titles, and reference-style link definitions.
- Kept `repair_markdown_quality()` idempotent so repeated repair does not keep changing content.

## Quality Scanning

- Expanded `scan_markdown_quality()` to detect orphan or redundant emphasis, empty image targets, relative local videos, heading-level jumps, suspicious code languages, non-breaking spaces in code, and unreplaced external WeChat media.
- Added destination parsing for regular links, images, nested Markdown nodes, and reference-style links without treating special characters inside destinations as prose defects.
- Exposed the additional signals through batch quality reports for downstream review workflows.

## Video SDK

- Added the public `ConvertedVideo` type.
- Added `ArticleConversionResult.videos` with source URL, Markdown path, local path, and extension.
- Reused already downloaded videos during retries and allocated later paths for new videos without overwriting existing files.
- Stopped safely with a warning when fixed filename or Markdown-path templates repeatedly collide.
- Resolved local media paths only when they point to real files inside the generated package.

Consumers that do not want to store video files can disable downloads:

```toml
[videos]
download = false
```

They can still use article video markers to direct readers to the original article.

## Browser Compatibility

- Kept published metadata on `playwright>=1.60,<1.61`, the line verified with the current stable Camoufox 0.4.11 browser protocol.
- Bound the npm wrapper to the matching Python package version and used `uvx.exe` directly on Windows.
